# Mock 8 — Full-length exam simulation, blueprint-built paper (60 questions)

**Take this timed and cold.**

| | |
|---|---|
| Questions | 60 |
| Time | 120 minutes |
| Format | 4 scenarios × 15 questions, as on the real exam |
| Multiple-response | 10 questions, each marked **(Select two.)** |
| Working pass mark | 43 / 60 |
| Answer key | `mock-08-answers.md` |

Domain spread: D1 16 · D2 11 · D3 12 · D4 12 · D5 9 (the blueprint weighting).

**How this paper was built, and why it differs from Mocks 3–7.**

Every paper since Mock 1 except Mock 7 was written with `LOG.md` open, targeting facts already
known to have been missed. That is why Mocks 4 and 6 returned 97% and why the log discounted both.
This one was generated from the **blueprint objectives and the domain notes only** — the miss list
was not consulted while writing. Whatever it happens to cover, it covers because the blueprint says
so, not because it was missed before. The score therefore means something closer to what Mock 1's
meant.

**Two construction changes, agreed 23 Aug after auditing Purcell's set:**

- **The length tell is inverted.** In Purcell's 60 the correct answer is nearly always the longest
  option and carries its own rationale. Here the correct answer is frequently the **shortest**, and
  embedded justification appears in wrong answers at least as often as in right ones. Picking the
  option that explains itself will actively cost you marks on this paper.
- **No rotating key.** Purcell's answers run a strict four-cycle per scenario. This key is balanced
  by letter (A 12 · B 14 · C 12 · D 12 across the 50 singles, each letter 5× across the ten
  select-twos) with no positional pattern.

Every question is self-contained. The scenario paragraph is background only.

## Scenario A — Kestrel Underwriting (Structured Data Extraction)

*Kestrel Underwriting writes marine cargo insurance. A Claude-based pipeline extracts structured
records from surveyor reports, bills of lading and packing lists — PDFs, scans and email — arriving
from hundreds of brokers and surveyors. About 30,000 documents are processed overnight, plus a
small queue where an underwriter is waiting.*

**1.** Surveyor reports include a salvage recommendation only when the surveyor judges the cargo
partially recoverable; most reports contain no such section. The field is currently required, and
the model is producing recommendations for total losses. What should the schema do?

- A. Keep it required, with an enum whose permitted values include `none_given`, so the absence is
  represented inside the type system rather than outside it
- B. Keep it required and add a post-extraction rule rejecting any recommendation that does not
  appear verbatim in the source text
- C. Make it optional and nullable
- D. Keep it required and instruct the model in the prompt to leave the field empty whenever the
  surveyor made no recommendation at all

**2.** Every bill of lading in this flow is machine-generated by the carrier and always carries a
booking reference in a fixed field. About 3% of extractions come back without one. How should the
field be declared?

- A. Required
- B. Nullable, with a post-processing step that recovers the reference from the document filename
  wherever it is absent from the extraction
- C. Optional, with the reference retrieved later from the carrier's booking portal at the point a
  downstream system actually needs it
- D. Nullable, with a validation rule rejecting null, so missing references surface as errors
  instead of propagating silently

**3.** The pipeline prompt asks for the cargo record "as JSON in your reply". Roughly one response in
fifteen fails to parse, and the failures follow no pattern. What is the reliable fix?

- A. Add six further few-shot examples of well-formed JSON, chosen to cover the layouts that have
  failed most often in production
- B. Wrap the parser in a lenient mode that repairs trailing commas, unescaped quotes and stray
  prose before the opening brace
- C. Set temperature to zero, so the output format stops varying between otherwise identical
  requests
- D. Declare the record as a tool input schema and return it through tool use

**4.** After that change every output validates against the schema. Roughly 2% of records still show
a declared cargo value that does not match the sum of the itemised values. What follows?

- A. A record that validates against a strict schema cannot contain an invalid total, so the
  discrepancy must originate in a downstream reporting fault
- B. Tool use removes syntax errors but not semantic ones — add a `calculated_total` field beside the
  declared value so discrepancies become visible
- C. Add a step after extraction that recomputes the total from the line items and overwrites
  whatever value the model returned
- D. Mark the total field required, so the model can no longer omit it and produce an apparent
  mismatch against the items

**5.** Three surveyors write dates as `07/03/26`, `2026-03-07` and `7 March 2026`, and weights as
`2,400 kg`, `2400KG` and `2.4 tonnes`. The schema already types both fields strictly, and
extractions still return mixed representations. What produces one consistent record?

- A. A normalisation layer after extraction, with a branch for each surveyor's known format
- B. A separate extraction prompt per surveyor, selected from the sending address on the covering
  email
- C. Format normalisation rules in the prompt, alongside the strict schema
- D. A looser schema accepting each surveyor's native representation as a plain string, reconciled
  by the consuming systems downstream

**6.** Two problems in the same records. Cargo damage categories keep expanding as new commodity
classes are underwritten, and unfamiliar damage types are being forced into the nearest existing
value. Separately, some packets state one port of loading in the bill of lading and a different one
in the packing list, and one of the two is being dropped without trace. Which two schema changes
address these? **(Select two.)**

- A. Raise the temperature so the model stops collapsing on to the categories it has seen most often
- B. An enum plus an `"other"` value and a free-text detail field
- C. Make the port field nullable, so a disagreement between the two documents resolves to null
- D. A `conflict_detected` boolean that records both values with their sources

**7.** An extraction fails validation with two named field errors, and the team is designing the
retry. Which two statements are correct? **(Select two.)**

- A. The retry request should carry the original document, the failed extraction and the specific

**15.** Two rules must hold on every submission without exception: no cover above £2m may be bound by

bound. Which two changes guarantee this? **(Select two.)**

- A. A system prompt stating both limits at the top and repeating them in every user turn
